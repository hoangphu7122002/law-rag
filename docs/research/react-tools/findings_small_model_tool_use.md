# Findings: small-model tool use (agent summary; thin, weak evidence, odd arXiv ids unverified)
- No clean accuracy-vs-tool-count curve for 1-4B. Closest: BFCL extended with variable tool-pool sizes (arXiv 2609.16540 App. D.4, no numbers seen). Toloka (vendor): off-the-shelf Qwen3.5-4B solved ~6 % of enterprise tasks with dozens of similarly named tools over ~30 turns; fine-tuned 4B reached 71 %; "4B near the floor" (toloka.ai blog).
- BFCL: Qwen3-4B-Instruct-2507 ~88.7 vs frontier 98.0, abstains 40/40 when no tool fits (tinygpt blog); Llama-3.2-1B ~38 % non-live AST; sub-1B much worse; TinyLLM up to 65.74 % for 1-3B; 4-bit quantization raises missed calls in small models (4B unaffected).
- Native vs prompted ReAct: secondary sources say Qwen recommends Hermes-style native format; use 8B+ for demanding calls (unconfirmed vs Qwen docs). No controlled 4B comparison (arXiv 2608.22472 compares prompt vs native on BFCL incl. Qwen3-8B, no results seen) → run it ourselves.
- Schema/description design: nothing citable; common advice: flat schemas, enums, few required params, distinct names, short descriptions with an example (unverified).
- Failures: malformed calls ~32 % of 200 sampled failures for qwen2.5:3b/7b and Functionary-Small (arXiv 2601.16280); Granite 4 Small retried the same missing-brace call 19 times (arXiv 2512.07497); loops linked to inlining big data blocks and repeated error recovery; context overflow: no source.
- Mitigations: explicit error messages (Granite recovered), fingerprint calls and stop on a repeat with no new evidence, "is a tool needed?" gate (anecdotal), cap turns, truncate tool output (own suggestion). All already in generate/react.py except the gate.
- Gaps: arXiv 2609.16540 tool-pool results, Qwen official function-calling docs, small-model tau-bench.
