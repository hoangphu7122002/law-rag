# arXiv 2611.09382 — "Exploring Weight-Space Programming: Capabilities, Generalization, and Limitations" (Hu et al., Shanghai AI Lab/Tongji/Fudan, 2026-11-06)
Empirical study, no new algorithm. An LLM agent ("GPT-6 Astra", Python env + GPU worker, 50 forward-tool requests, no gradients) edits Qwen3.5-0.8B/9B transformer-block weights directly (sparse MLP edits, rank-one, head rescale), θ+Δθ in bf16, picks checkpoint by dev feedback. 16 trajectories, 7 benchmarks.
Held-out: 0.8B MATH-500 8.35→37.80 (1,023 values in one layer-23 MLP down-proj column), IFEval 21.4→58.1, SciBench 1.4→18.5, GPQA-D +4.4; 9B +1.5..3 pts (little headroom). 6/16 runs kept original weights; 9B Math dev +29.7 but held-out −0.35. Run-to-run variance large (+29/+5/+27). No LoRA/SFT baseline. Code: github.com/WSP-Scope/WSP-Scope-Project.
Fit to law-rag: needs a frontier agent + large clean dev set per task; dev gains often fail held-out (our dev=300, test already used for selection); gains shown on a weak 0.8B base with cheap-to-fix failure modes, ours is tuned 2B whose limit is label ambiguity/quote extent. Not applied. Cheap related ideas we already ran: weight soup/interpolation (no gain).
